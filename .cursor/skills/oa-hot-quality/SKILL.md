# 火星空间探索 · 热点优质文 → 草稿箱

发稿号固定 **火星空间探索**（`brandKey: mars_space`）。  
写完 + 专属图 → **必须入库**「内容中台 → 草稿箱」。运营自己预览、自己点「推微信」。

**记住了：我叫你写热点你就根据技能写出来并推送到草稿箱。**

## 和别的技能分开

| 需求 | 走哪个 |
|---|---|
| 热点 / 辟谣 / 信息差 / 贴图 | **本技能** |
| 产品更新、技巧连载、商家教程 | `oa-update-log`（火星探索日志） |
| 只排版不写稿 | `xiaohu-wechat-format` |
| 小红书发射科普 / 观礼 | `xhs-launch-edu` / `xhs-watch-party-merchant` |

## 先过门槛（不过就不要写成热点）

账号检测绿 ≠ 推荐会推。近 30 天已验证：

- **进池：**「图是不是假的」这类争议短图文；关键节点 **贴图**
- **不进池：**「某某公司宣布 / 曝光 / 目标」；财报、电话会复盘
- 推荐来得快、当天走。没开群发时，进不了池的稿只剩几十阅读

**写（推荐向）**

- 有人正在传、但能判断真假或对错的一句
- 时间、地点、图、数字对不上
- 发射 / 回收 / 在轨的 **关键节点**，且有能说话的图

**不写热点（直接说、或改成粉丝向深度稿）**

- 标题像通稿：曝光、宣布、目标、复盘财报
- 同火箭 / 同公司 / 同事件，**4 天内已经发过推荐向**
- 编造、洗稿、把生成图当成现场实拍
- 一次连发多条换皮新闻

一周推荐位只押 **1～2 条**。用户没说「写 N 篇」就只写 1 篇。

选题细节与否决句式见 [examples.md](examples.md)。

## 体裁怎么选

| 情况 | 体裁 | 篇幅 |
|---|---|---|
| 一句能抬杠（真假、对错、传错了） | **A 短图文** | 350～700 字 |
| 节点动态 + 图本身是信息 | **B 贴图** | 标题 ≤32 字，说明 80～180 字 |
| 用户明确要复盘 / 讲透 | **C 粉丝向** | 800～1500 字；不指望推荐 |

拿不准时：能写成「结论先行的一句」→ A；只能报动态 → B；要分析过程 → 先问是不是 C，默认不当热点硬写。

## 工作流（同一轮做完）

复制并勾：

```
- [ ] 门槛：不是通稿 / 不是 4 天内膜
- [ ] 搜公开报道，核时间地点数字；核不住就停
- [ ] 选定 A / B / C
- [ ] 扫 docs/wechat-oa/**/article.md 近 7 天标题（不限 hot-*）
- [ ] 问清微信已发表是否刚发过同火箭/同公司（仓库里没有那 252 篇）
- [ ] 落盘 article.md + 专属图（目录里不要留没用到的图）
- [ ] 入库 mars_space 草稿箱
- [ ] 回复：体裁、目录、草稿 id、已带专属图
```

### 1. 核事实

用搜索核：时间（写清时区）、地点、主体、数字、图的来源。  
只写能指回公开报道的判断。不确定就写「公开报道是……」，禁止脑补。

### 2. 落盘

目录：`docs/wechat-oa/hot-YYYY-MM-DD-短名/`

**A 短图文** `article.md`（标题建议 ≤32 字，最长 64）：

```markdown
---
type: news
brand: mars_space
---
# 标题写成结论或争议（短，像能转的那句）

![封面](cover.jpg)

开场一句把事说完。

## 为什么容易信错
两三个短句，不堆背景。

## 怎么判断
可核对的点（时间 / 图 / 官方口径）。数字用「约 / 公开报道」。

结尾只留 **一句关注理由**（下次这类图怎么辨、下一节点盯什么）。
禁止篇篇「微信搜小程序」。
```

**B 贴图** `article.md`（标题 ≤32 字）：

```markdown
---
type: newspic
brand: mars_space
---
# 标题不超过三十二字

![封面](cover.jpg)

两三段把节点说完。不写小程序口令，不堆话题（导入会补 #话题#）。
```

**C 粉丝向**（仅用户明确要复盘 / 讲透；结构不要套辟谣）：

```markdown
---
type: news
brand: mars_space
---
# 标题写读者能带走的一句，不要「复盘/一文看懂」

![封面](cover.jpg)

先说这件事现在卡在哪。

## 公开信息里能确定的
节点、数字、来源。用「约 / 公开报道」。

## 还不能确定的
缺什么、别当成已经发生。

收尾一句即可，不导小程序。
```

### 3. 专属图（强制）

- 必须有本篇 `cover.jpg`（或 `cover.png`），文首引用。禁止默认封面、禁止套旧图。
- 比例：图文封面 **16:9**；贴图主图 **4:3** 或 **1:1**。
- 用 `GenerateImage` 出图后 **复制到该目录** 再入库。
- 具体火箭外形需要对时，用 `.cursor/skills/xhs-watch-party-merchant/assets/rocket-refs/` 作 `reference_image_paths`。
- **辟谣 / 辨假：** 封面必须是示意图或对比示意，画面里能看出「不是现场实拍」。禁止生成以假乱真的事故/爆炸现场图。
- 贴图 1～4 张；图文封面 + 最多 1 张文内图。图不够信息不增，就不要硬配。

### 4. 入库（不是推微信）

```bash
node scripts/ops-admin-login.js
OA_BRAND_KEY=mars_space node .cursor/skills/oa-update-log/scripts/import-to-drafts.js docs/wechat-oa/hot-YYYY-MM-DD-短名
```

- 贴图：文首 `type: newspic`，或加 `--newspic`
- 发稿号：文首 `brand: mars_space`，或 `--brand mars_space`；目录名 `hot-*` 也会默认空间号
- 无 token 先登录；缺封面时 `--dry` 也会失败
- **不要**调用推微信 / 群发。回复写清：已进内容中台草稿箱，未推微信
- 图文入库后中台仍可能加文首免责（含小程序名），不要再在正文里加第二句导流

## 文风

1. 简体中文、短句、有判断。品牌「火星空间探索」。
2. 标题像人话结论，不像新闻通稿。
3. 禁止内部词（云函数、COS、过审、token、洗稿）。
4. 禁止空话、禁止复述新闻五段背景。
5. 不洗稿。可引用公开事实，判断必须是自己的。

## 回复用户时带上

- 过没过门槛、选了 A/B/C、为什么
- 本地目录、是否专属封面
- 入库 id / 标题；未推微信
- 一句：这类稿推荐是当天票，发之前确认 4 天内没发过同题材
