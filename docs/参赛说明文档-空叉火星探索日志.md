## 一、作品简介

「空叉火星探索日志」（以下简称「火星探索日志」）是一款面向中文航天爱好者的微信小程序。它以全球火箭发射实时追踪为核心，覆盖星链过境观测、星舰进度、航天事件与 NASA 数据，并内置航天助手「星问」，让用户可以用自然语言理解复杂航天信息、直达业务功能。

一句话概括：**把实时发射数据、星链观测与星舰进展，和内置航天 AI 助手绑在一起的太空探索日志。**

主要能力包括：


| 模块    | 能力概述                            |
| ----- | ------------------------------- |
| 主页    | 全球发射倒计时、任务详情、图文视频动态、开屏体验        |
| 监控中心  | 直播、星链过境/分布、空间站、轨道地图、发射商与助推器图鉴   |
| 星舰进度  | 星舰硬件与事件、Starbase / 封路地图、任务模拟指挥室 |
| 事件    | 航天动态、文章与影像                      |
| 星问 AI | 流式航天问答、意图识别出业务卡片、智能搜索与识图        |
| 我的    | 签到知识卡、成就、竞猜、会员「星际通行证」、年度回顾      |

## 二、创作背景

### 2.1 命题理解：「与AI共生」

「共生」不是把聊天框塞进产品里，而是让 AI 成为用户与复杂世界之间的**翻译层与导航层**：

- **AI 负责理解与讲解**：自然语言提问、识别意图、把专业术语说成人话；
- **小程序负责权威数据与操作**：实时发射库、轨道计算、页面跳转、会员与内容分发；
- **人负责判断与把关**：运营审核公众号稿件、用户确认关键操作、免责声明与配额约束。

本作品希望回答的问题是：在微信里，航天爱好者如何与 AI **一起读懂发射、一起观测星链、一起跟进星舰**——而不是只与 AI「闲聊太空」。

### 2.2 现实痛点

航天信息本身高度专业，且分散在多语言官网、推文、直播与第三方数据库中：

1. **信息碎片化**：下次发射何时？从哪座发射场？载荷是什么？中文侧缺少一站式入口；
2. **门槛高**：TLE、仰角方位、GO/NO-GO、助推器复飞等概念，普通用户难以快速理解；
3. **时效强**：发射窗口、封路、过境窗口以分钟计，静态百科无法满足「当下」需求；
4. **表达隔阂**：权威数据多为英文，爱好者需要可读的中文解读与可操作的观测指引。



### 2.3 为什么做在微信小程序

微信是中文用户最高频的入口。把航天数据与 AI 能力放进小程序，意味着：

- 无需安装独立 App，扫码即用；
- 可与公众号内容生产、分享卡片、订阅提醒形成闭环；
- 可对齐微信云开发 AI（混元）与微信 AI 生态，让「与微信共生、与 AI 共生」落到同一条产品链上。



### 2.4 创作动机

作者本人是航天爱好者。在长期跟进 SpaceX / 星舰 / 星链与全球发射动态的过程中，逐渐把「自己想随时查的东西」做成了可用的产品：倒计时要准、星链要看得见、星舰进度要跟得上，再用「星问」把这些能力串成自然语言入口。作品名称中的「空叉」是 SpaceX 的谐音梗，也体现社区口语与产品温度；「火星探索日志」则指向更长远的探索叙事——从地球轨道到深空，从记录发射到陪伴用户一起成长。

## 三、创作思路



### 3.1 总体理念：数据为骨，AI 为脉，交互为面

```text
权威数据管线（LL2 / TLE / 推文 / NASA …）
        ↓
小程序业务能力（发射 / 星链 / 星舰 / 事件 …）
        ↓
AI 共生层（星问对话 · 智能搜索 · 识图 · 翻译 · 内容中台）
        ↓
用户一句话即可理解与行动
```

核心理念可以概括为三句话：

1. **AI 不替代数据，只连接数据**——发射时间、轨道位置以权威源为准，模型禁止编造窗口；
2. **AI 不只回答，还能带路**——识别意图后给出可点击的业务卡片，直达发射列表、星链过境、星舰进度等；
3. **AI 贯穿生产与消费**——用户侧问答检索，运营侧洗稿分发，形成「数据 → AI → 多端内容」闭环。



### 3.2 产品结构：五 Tab + 全域助手

- **主页**：面向「下一发」——倒计时与任务入口；
- **监控中心**：面向「天上在发生什么」——直播、星链、空间站、轨道；
- **星舰进度**：面向「最受关注的工程进展」——硬件、基地、模拟指挥；
- **事件**：面向「故事与动态」——文章、影像、热点；
- **我的**：面向「长期陪伴」——签到、知识卡、会员与成长；
- **星问**：悬浮于各主 Tab，作为跨模块的自然语言入口。



### 3.3 「与AI共生」的三层设计



#### （1）用户侧共生：星问

- 基于微信云开发 AI+ 混元模型流式对话；
- 自动注入即将发射 / 已完成任务等实时上下文；
- 意图识别后输出富消息卡片，用户可一键进入对应功能；
- 智能搜索并行给出任务检索结果与 AI 简答；
- AI 识图：OCR + 混元判断是否航天相关并识别型号。

设计原则：**懂航天的助手，而不是万能闲聊机器人**。系统提示词明确能力边界，引导用户回到小程序真实功能。

#### （2）内容侧共生：中文化与公众号中台

- 发射数据、SpaceX 推文等经 LLM 批量翻译，降低阅读门槛；
- 公众号内容工作室用 AI 完成素材理解、洗稿、插图槽位编排，再经人工审核推送草稿；
- 提示词策略强调「去 AI 味、事实红线、品牌人设」，避免幻觉污染科普内容。



#### （3）生态侧共生：对齐微信 AI

- 小程序内已跑通「星问」；
- 同步规划微信 AI **自动模式**（平台理解页面并代操作）与 **开发模式 SKILL**（原子接口 + 原子组件）；
- 已预留发射、星舰、助推器、空间站等 Skill 骨架，使未来微信 AI 可直接调用本小程序的实时航天能力。



### 3.4 体验原则


| 原则    | 落地方式                             |
| ----- | -------------------------------- |
| 实时优先  | Launch Library 2 等数据同步 + 云函数查询缓存 |
| 可视化优先 | 轨道地图、星链全屏渲染、AR 过境、飞行剖面           |
| 科普可玩  | 指挥室 GO/NO-GO 模拟、知识卡签到、晨间简报       |
| 可信可控  | AI 免责声明、会员配额、运营审核、过审开关           |
| 微信原生  | 云开发、分包懒加载、自定义 TabBar、分享卡片        |

## 四、实践过程



### 4.1 阶段一：立住「发射日志」骨架

从最刚需的全球发射追踪起步：

- 对接 The Space Devs / Launch Library 2，建立发射同步与查询云函数；
- 完成首页倒计时、任务详情、监控与事件等基础信息架构；
- 用微信云开发承载后端，保证小程序内低门槛访问。

目标：让用户「打开就能看到下一发火箭」。

### 4.2 阶段二：把「看得见」做成差异化

在信息列表之上叠加观测与可视化：

- **轨道地图**：基于 TLE 展示空间站等目标位置与轨道；
- **星链**：过境计算、全屏星座渲染、AR 观测（结合模糊定位权限）；
- **星舰专项**：硬件列表、Starbase / 封路地图、飞行剖面与指挥室模拟；
- **NASA 数据**：火星车影像、EONET、近地天体等扩展科普面。

目标：从「查发射」升级为「观察天空与工程进展」。

### 4.3 阶段三：接入 AI，完成「与AI共生」闭环



#### 4.3.1 星问助手

- 封装 `aiService`：混元流式对话、上下文注入、降级策略；
- 开发 `ai-chat` 组件与富消息卡片，把自然语言接到业务页；
- 在搜索页并行调用智能回答，缩短「搜到」到「看懂」的路径；
- 云函数 `aiImageRecognize` 实现航天相关识图。



#### 4.3.2 AI 翻译与内容中台

- 发射数据、推文等内容的 LLM 中文化管线；
- 管理后台建设公众号 Pipeline：素材 → 策略提示词 → 生成/洗稿 → 插图 → 草稿推送；
- 定时任务支持日更触发，形成可持续的内容生产节奏。



#### 4.3.3 工程与运营配套

- Vue3 管理后台：开屏、轮播、知识卡、会员、OA 内容等配置；
- Workers：B 站动态发布、回放拉取至 COS 等；
- 会员「星际通行证」：对 AI 次数、AR、回放等能力做合理门控，保障服务可持续。



### 4.4 阶段四：向微信 AI 生态演进

- 梳理现有原子能力，编写《小程序 AI 能力被微信 AI 调用接入文档》；
- 预留 `agent-skills`（发射 / 星舰 / 助推器 / 空间站等）；
- 明确自动模式与开发模式的分工：页面可达用自动模式，结构化实时查询用 Skill。

实践体会：**先把业务做深，再让 AI 调用业务**，比先做空壳对话更符合「共生」。

### 4.5 技术架构概览

```text
┌─────────────────────────────────────────────┐
│              微信小程序前端                  │
│  主页 / 监控 / 星舰 / 事件 / 我的 / 星问     │
└──────────────────┬──────────────────────────┘
                   │ 云开发
┌──────────────────▼──────────────────────────┐
│ 云函数：同步 · 查询 · 会员 · 识图 · OA 中台  │
│ 云库 / COS：配置、内容、媒体资产             │
│ 云开发 AI+：混元对话 / 翻译 / 生成           │
└──────────────────┬──────────────────────────┘
                   │
     ┌─────────────┼─────────────┐
     ▼             ▼             ▼
 外部数据源      管理后台      Workers / 边缘
 LL2·TLE·NASA   Vue3 Admin   发布·回放·代理
 推文·NSF …
```

**技术栈要点**：

- 前端：原生微信小程序（WXML / JS / WXSS）、分包、懒加载、自定义 TabBar；
- 后端：微信云开发云函数与云数据库；
- AI：微信云开发 AI+ 混元（主），必要时外部模型兜底；
- 管理端：Vue 3 + Vite + Element Plus；
- 数据：Launch Library 2、TLE、NASA、NextSpaceflight、公开推文源等。



### 4.6 关键实践难点与取舍

1. **幻觉控制**：问答强制优先任务上下文；内容中台设事实红线与人审；界面展示 AI 生成免责声明。
2. **实时与成本**：高频数据走同步+缓存；AI 对话/识图设免费额度与会员/广告补充。
3. **包体积与性能**：能力拆分包；星链渲染与视频资源按会员与网络策略控制预加载。
4. **过审与合规**：AI 总开关可配置；定位仅用模糊位置服务观测计算；隐私协议与用户告知齐全。

## 五、作品亮点（对照命题）

1. **真正的人机共生产品形态**
  星问不是孤立聊天窗，而是「自然语言 → 意图 → 业务卡片 → 权威页面」的完整链路。
2. **垂直场景下的 AI 价值最大化**
  聚焦航天，系统提示词、识图、翻译、洗稿全部围绕同一领域，比泛娱乐问答更可验证、更有用。
3. **数据 × AI × 微信生态**
  实时发射与轨道数据托底；混元承担理解与表达；小程序与公众号、分享、云开发同属微信生态。
4. **可视化与可玩性**
  轨道地图、星链渲染/AR、指挥室模拟，让 AI 讲解有「可看见、可点击」的落点。
5. **可演进的微信 AI 接入路径**
  已有站内助手与 Skill 骨架，具备对接微信 AI 自动模式与开发模式的基础。

## 六、使用说明（评审快速体验）

1. 微信扫码打开「火星探索日志」；
2. 主页查看全球发射倒计时，进入任务详情；
3. 监控中心体验星链过境 / 轨道相关能力（按需授权模糊定位）；
4. 星舰进度查看工程进展，可体验模拟指挥相关入口；
5. 通过悬浮入口打开「星问」，试用例如：
  - 「下一发猎鹰 9 什么时候」  
  - 「今晚星链过境怎么看」  
  - 「星舰最近进度」
6. 搜索页可试用智能回答与识图（受每日额度限制）。

## 七、总结

「空叉火星探索日志」把航天实时数据做成可查、可看、可玩的微信小程序，再用「星问」与内容中台让 AI 成为用户理解太空、运营生产科普的共生伙伴。

我们相信：**与 AI 共生，不是把人交给模型，而是让模型帮人更快地抵达真实世界里正在发生的发射、过境与探索。**
